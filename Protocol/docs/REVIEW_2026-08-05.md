# Solana review — 5 August 2026

> **Historical record — superseded.** This review predates protocol version 6 and its revised fee
> routing. Its 8%/2%/2% fee statement and deployment conclusions must not be used as current
> readiness evidence. See `MAINNET_READINESS.md` and `MAINNET_LAUNCH_RUNBOOK.md` for active gates.

## Outcome

The protocol is implemented and suitable for local testing and paused devnet preparation. It is
not a mainnet approval: devnet deployment/initialization, trusted randomness operations,
production authorities and the external Meteora fee flow still require explicit operational
confirmation.

## Controls reviewed

- Program IDs are synchronized across `declare_id!`, `Anchor.toml`, the IDL build and clients.
- Anchor and Solana versions are pinned; Cargo and pnpm lockfiles are present.
- Initialization derives a single config PDA and verifies the real upgradeable ProgramData account.
- The upgrade authority must sign initialization, preventing first-caller takeover.
- Mint owner, token program, decimals, supply, mint authority and absent freeze authority are checked.
- Admin-only changes use PDA seed/bump validation plus `has_one`; transfers require acceptance by the
  proposed signer.
- Arithmetic helpers reject invalid basis points and overflow; release overflow checks remain on.
- The protocol begins paused and economic constants cannot be changed through an instruction.
- `cargo audit` reports no known vulnerabilities. It does report the upstream unmaintained warning
  for `bincode 1.3.3` (`RUSTSEC-2025-0141`), inherited through the pinned Solana/Anchor stack.

## Remaining risks before value movement

- Devnet has not yet been deployed or initialized; the configured program account is currently
  absent and the intended devnet wallet must be funded before deployment.
- Local trusted-randomness settlement is implemented; the devnet randomness signer and its
  failure/staleness runbook must be confirmed before unpausing.
- Trading-fee collection is deferred and is not part of this milestone. Staking is funded by the
  on-chain 8% mining allocation; Motherlode receives 2% and buyback/burn receives 2%.
- Upgrade and operating authorities are still single keys for devnet; production governance and
  incident response are undecided.
- The frontend's main product routes remain a safe preview, not an on-chain transaction client.

Any implementation of those surfaces requires new adversarial tests and another security review.
